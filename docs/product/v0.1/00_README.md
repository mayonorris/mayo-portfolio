# Mayo Portfolio Website Documentation Pack

Version: 0.1
Status: Working draft
Product owner: Mayo T. N. Kadanga
Product type: Personal portfolio, research hub, and professional proof system
Primary stack: Next.js + Quarto
Primary languages: English and French

## Purpose

This documentation pack converts the initial brainstorming into an actionable product definition for a modern personal portfolio website.

The portfolio is not designed as a visual CV. It is designed as a professional proof system that demonstrates how Mayo transforms economic, statistical, institutional, and technical problems into decision-ready analysis, digital products, and research outputs.

## Strategic summary

### Core positioning

**Economic Data Scientist and Full-Stack Analytics Builder**

Mayo combines:

- economic and statistical analysis;
- data science and econometrics;
- public-sector and institutional consulting;
- interactive analytical applications;
- full-stack web development;
- research, teaching, and technical writing.

### Core promise

**From evidence to decisions. From models to digital systems.**

### Product concept

**Editorial Intelligence Portfolio**

The visual and interaction model combines:

- institutional credibility;
- editorial clarity;
- data-native visual language;
- selected high-value interactions;
- rigorous project documentation;
- scientific publishing through Quarto.

### Architecture

Next.js manages the flagship portfolio:

- home;
- selected work;
- case studies;
- about;
- experience;
- contact;
- interactive components.

Quarto manages the knowledge layer:

- research;
- technical notes;
- reproducible analyses;
- teaching;
- publications;
- citations;
- R and Python outputs.

### Primary conversion goals

1. View a selected case study.
2. Download or open the CV.
3. Explore research or technical work.
4. Contact Mayo for a role, consulting engagement, research collaboration, or speaking opportunity.

## Working method

Each important choice should move through four states:

1. Assumption
2. Proposal
3. Validated decision
4. Implemented and tested

The decision log must be updated whenever an architectural, content, UX, or visual choice becomes final.
