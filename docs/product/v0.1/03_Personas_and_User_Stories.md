# Personas, Jobs to Be Done, and User Stories

Version: 0.1
Status: Draft for validation

## 1. Persona: Hiring manager

### Context

A hiring manager is evaluating candidates for a role in:

- data analytics;
- data science;
- economic analysis;
- research;
- monitoring and evaluation;
- analytics engineering;
- decision-support systems.

### Needs

- rapid understanding of Mayo's profile;
- evidence of relevant delivery;
- clear experience history;
- accessible CV;
- confidence in communication ability;
- proof of technical depth.

### Main concern

The profile may initially appear too broad.

### Job to be done

When evaluating Mayo, I want to see a small number of relevant projects and understand his exact contribution, so I can decide whether to move him to the next recruitment stage.

### User stories

- As a hiring manager, I want to understand Mayo's positioning within 30 seconds.
- As a hiring manager, I want to filter or scan projects by domain.
- As a hiring manager, I want to see outcomes, not only tools.
- As a hiring manager, I want to download a current CV.
- As a hiring manager, I want to verify technical depth through code or detailed notes.
- As a hiring manager, I want a direct way to contact Mayo.

## 2. Persona: Institutional decision-maker

### Context

A public institution, development organization, consulting firm, or research organization is considering Mayo for a mission or collaboration.

### Needs

- evidence of methodological rigor;
- understanding of public-sector constraints;
- ability to produce operational deliverables;
- ability to work across data, analysis, and digital systems;
- professional credibility.

### Job to be done

When considering a consultant or technical partner, I want to verify that Mayo can handle both analytical rigor and implementation, so I can reduce delivery risk.

### User stories

- As an institutional decision-maker, I want to see projects similar to my context.
- As an institutional decision-maker, I want to understand the methodology at a non-specialist level.
- As an institutional decision-maker, I want to know which outputs were delivered.
- As an institutional decision-maker, I want to see how confidentiality is handled.
- As an institutional decision-maker, I want to contact Mayo for a scoped discussion.

## 3. Persona: Research supervisor or academic evaluator

### Context

A researcher, doctoral supervisor, or admissions committee member is reviewing Mayo's research potential.

### Needs

- coherent research agenda;
- methodological evidence;
- writing quality;
- reproducibility;
- clear educational and professional background;
- accessible proposals, papers, and technical notes.

### Job to be done

When evaluating Mayo's research potential, I want to inspect his questions, methods, and written outputs, so I can assess fit and readiness.

### User stories

- As a research evaluator, I want to see Mayo's current research themes.
- As a research evaluator, I want to access technical documents with citations.
- As a research evaluator, I want to inspect reproducible R or Python work.
- As a research evaluator, I want to distinguish completed work from work in progress.
- As a research evaluator, I want to access the academic CV.

## 4. Persona: Technical peer or collaborator

### Context

A data scientist, engineer, statistician, or developer wants to evaluate Mayo's technical practice.

### Needs

- architecture decisions;
- code quality;
- implementation details;
- reproducible examples;
- links to repositories;
- evidence of trade-off analysis.

### Job to be done

When evaluating a possible collaboration, I want to understand how Mayo designs and implements solutions, so I can assess technical compatibility.

### User stories

- As a technical peer, I want to inspect repositories associated with public projects.
- As a technical peer, I want to understand the stack and architecture.
- As a technical peer, I want to see what Mayo personally implemented.
- As a technical peer, I want to read concise technical notes.
- As a technical peer, I want to distinguish production code from learning experiments.

## 5. Persona: Student or learner

### Context

A student finds Mayo through a course, article, or search result.

### Needs

- understandable explanations;
- structured resources;
- code examples;
- teaching materials;
- clear usage rights.

### Job to be done

When learning a statistical, economic, or programming topic, I want to access a structured explanation and reproducible example, so I can apply the concept correctly.

### User stories

- As a learner, I want to browse notes by topic.
- As a learner, I want code and outputs in the same article.
- As a learner, I want to know the expected level.
- As a learner, I want links to related resources.

## 6. Product-owner stories

- As Mayo, I want to add a research note without changing the Next.js codebase.
- As Mayo, I want to publish R and Python outputs through Quarto.
- As Mayo, I want to add a case study using a reusable content structure.
- As Mayo, I want English and French content to remain consistent.
- As Mayo, I want one shared visual identity across both systems.
- As Mayo, I want to update the CV without redesigning the website.
- As Mayo, I want analytics that measure useful actions without invasive tracking.
- As Mayo, I want project content to support different confidentiality levels.
- As Mayo, I want the site to remain maintainable as the portfolio grows.

## 7. Priority stories for Version 1

### Must have

- Understand positioning quickly.
- View selected case studies.
- Read clear contribution and outcomes.
- Open or download CV.
- Explore research.
- Contact Mayo.
- Use the site on mobile.
- Navigate with a keyboard.
- Switch between English and French.
- Publish new Quarto content independently.

### Should have

- Browse projects by domain.
- Link case studies to deeper technical notes.
- View code or repository links.
- See current focus.
- Use dark or light theme preference.

### Could have

- Unified search.
- Interactive project filters.
- Advanced data-story interaction.
- Personal reading list.
- Newsletter.

### Will not have in Version 1

- User accounts.
- Comments.
- Full CMS.
- AI assistant.
- Large 3D environment.
